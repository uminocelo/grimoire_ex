Grimoire v0.1.0 is out. It's a static site generator for Elixir with
exactly one runtime dependency: [Alembic](https://hexdocs.pm/alembic_template_engine),
the Liquid-compatible template engine it's built on. Everything else —
front matter parsing, Markdown, RSS/Atom/sitemap generation, the dev
server, the file watcher — is Elixir and OTP standard library, nothing
more.

## What's in the box

- **Content pipeline**: a hand-written front matter parser (no YAML
  dependency), Markdown rendering, and a file scanner that discovers
  `_posts/`, `_pages/`, `_layouts/`, `_includes/`, and `assets/`.
- **Renderer**: Alembic-backed layout inheritance, a template context
  covering `site.*`/`post.*`/`page.*`/`paginator.*`, and six custom
  filters — `date_to_string`, `date_to_xmlschema`, `xml_escape`,
  `slugify`, `relative_url`, `absolute_url`.
- **Builder**: parallel rendering across BEAM schedulers via
  `Task.async_stream/3`, pagination, tag and category archive pages,
  RSS 2.0 and Atom 1.0 feeds, `sitemap.xml`, and an asset pipeline with
  optional MD5 cache-busting fingerprints.
- **Dev server and watcher**: an `:inets`-backed local server and a
  polling file watcher with debounced rebuilds — save a file, see the
  change in under a second, no restart.
- **Two ways to run it**: `mix grimoire.*` tasks if you're already in an
  Elixir project, or a standalone `grimoire` escript binary that only
  needs Erlang on `PATH`.

## Dogfooding

This site — the one you're reading right now — is built with Grimoire,
using Grimoire's own layouts and the guides shipped in `docs/`. If
something here looks broken, that's Grimoire's bug, found the same way
every other bug in this release was found: by actually running the thing,
not just trusting a green test suite.

## Try it

```console
$ grimoire new my_blog && cd my_blog
$ grimoire build
$ grimoire serve
```
