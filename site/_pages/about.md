Grimoire is a static site generator for Elixir with one runtime
dependency: [Alembic](https://hexdocs.pm/alembic_template_engine), the
Liquid-compatible template engine it renders through. Everything else —
front matter parsing, Markdown, the parallel builder, RSS/Atom/sitemap
generation, the dev server, the file watcher — is built entirely on
Elixir and OTP's standard library.

This site is generated by Grimoire itself, from the `site/` directory in
[the Grimoire repository](https://github.com/uminocelo/grimoire_ex) — the
same pipeline that builds any Grimoire site, dogfooded on Grimoire's own
project pages.

## Design constraints

- **Zero runtime dependencies beyond Alembic.** No YAML library, no XML
  library, no HTTP client library — Markdown, front matter, feed/sitemap
  XML, the dev server, and the file watcher are all hand-built on
  OTP/Elixir stdlib.
- **One broken thing doesn't abort the build.** A single post or page
  that fails to render, or a broken archive-page layout, is recorded in
  the build result and the rest of the site still builds. Only a genuine
  URL collision between two posts/pages aborts before anything is
  written.
- **Parallel by default.** Content parsing and rendering both use
  `Task.async_stream/3` across BEAM schedulers.
- **Two ways to run it.** `mix grimoire.*` tasks for projects already
  using Elixir/Mix, or a standalone `grimoire` escript binary that only
  needs Erlang on `PATH`.

## Source and issues

Grimoire is developed in the open at
[uminocelo/grimoire_ex](https://github.com/uminocelo/grimoire_ex).
Alembic, its template engine, is a separate, independently useful
project — see its own
[documentation](https://hexdocs.pm/alembic_template_engine).
